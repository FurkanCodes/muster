# Muster Desktop: the build plan

The brief every branch of the desktop app works from. What the app is: `PRODUCT.md` §6a. How it is built: `ARCHITECTURE.md` §5c, rules `ARC-24` and `ARC-25`. What it looks like: the design canvas (every screen, measured) and the Muster design system, whose tokens and component CSS are `src/styles/tokens.css` and `src/styles/components.css`. Copy, keys and behaviour follow the terminal UI wherever the TUI already does the thing: read its code (`crates/muster-tui`) for what a screen says and does.

## Branches

All branch from `feature/desktop-app` (the foundation) and merge back into it with `git merge --no-ff`. Each owns the folders named; touching another's is a note in the merge, kept small.

## How every branch works

- **Read first:** `PRODUCT.md`, `ARCHITECTURE.md` (§5c), `CLAUDE.md`, this file, and the design system's README (`src/styles/` and the canvas). Use the `vercel-react-best-practices` and `vercel-composition-patterns` skills while writing React, and `web-design-guidelines` before you finish.
- **Types come from Rust.** Use `src/ipc/generated` (`pnpm bindings` after any Rust type change). Never hand-write a protocol type. Commands are the daemon's `Command`, sent with `useBridge().command(...)`; answer them in the mock (`src/ipc/mock/commands.ts`) as the real daemon would, from its code.
- **State:** read the daemon through `useDaemon(selector)` and select the smallest thing (a string, a number, one entity); `useShallow` for lists of ids. The window's own state is `useUi`/`useActions`; a screen's private state stays in the screen.
- **Look:** only the design system's classes and tokens; a new reusable part goes into `src/ui/` and, if the design system lacks it, is noted for it. No inline colours, no new fonts, no emoji, no icon packages (`src/ui/Icon.tsx` draws icons).
- **Frugal (`ARC-25`):** no timers but the clock (`useNow`), no polling, nothing that animates by script, nothing streamed while hidden, every listener removed on unmount, no barrel files, heavy parts loaded with `lazy()`.
- **Keys:** every action has a key (`useKeys`) and a hint (`useActions().setHints`), the same keys as the TUI's.
- **Tests, always, in the same commit as the code:** unit and component tests beside the code (`*.test.ts(x)`, Vitest), and end-to-end tests of the screen in `e2e/<area>.spec.ts` (Playwright, WebKit, over the mock), each driving the mock daemon (`window.__muster`) to show a state and asserting what the person sees. A screen is done when its states from the canvas (empty, loading, error, each variant) each have a test.
- **Before each commit:** `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm e2e`; for Rust, `cargo fmt --check`, `CARGO_BUILD_WARNINGS=deny cargo clippy --all-targets` and the tests of what changed. No file over 1,000 lines (`ARC-08`).
- **Commits:** small, each a whole step with its tests, messages in the repository's voice citing the rules they touch (`PRD-*`, `ARC-*`). Never commit to `feature/desktop-app` or `main` directly; never push.
